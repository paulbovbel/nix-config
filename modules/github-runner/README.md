# GitHub Runner

The GitHub runner module operates a disposable per-job self-hosted Actions runner for one repository.

## Requirements

The runner requires an agenix-managed GitHub access token in
`secrets/server/github-runner-token.age`. Use a long-lived PAT with permission to
register runners for the configured repository (classic PAT: `repo` for private
repositories; fine-grained PAT: repository Administration read/write). A temporary
runner registration token expires and cannot support repeated registration.
Its configured labels must match the workflow labels that select it.

Private flake inputs use the existing agenix-managed SSH key, mounted read-only at
`/run/agenix/github-runner-ssh-key`. The runner selects it through
`GIT_SSH_COMMAND` for Git and `NIX_SSHOPTS` for Nix's native LFS fetcher, which
invokes SSH directly rather than using Git's command override.

## Job lifecycle and state

Each fresh container registers an ephemeral runner, accepts one job, and powers
off when the runner exits, including registration or listener failures. The host
restarts the container after one second. The runner service never restarts inside
a used container, including after retryable failures.

Registration state, home, workspace, tool configuration, temporary files, and
guest logs live in the disposable container filesystem. No runner state directory
is bind-mounted from the host. Stopping `container@github-runner.service`
explicitly leaves it stopped; normal guest exit causes replacement.

The NixOS container still shares the host's Nix store, daemon, and per-container
Nix profiles/GC roots. These are build-cache state, not a fresh-machine isolation
boundary. Attic provides external caching. Credentials are injected through
read-only mounts; they are not generated by jobs or stored in a persistent home.

## Troubleshooting

Inspect the host `container@github-runner.service`, then inspect
`github-runner-nix-config.service` inside the running container for registration
or job failures. Its home and workspace are `/var/lib/github-runner/work`; the
access token is mounted at `/run/secrets/github-runner-token`. Inspect guest logs
before the job exits, because replacement discards them. Repeated
container restarts usually indicate registration failures; verify the token type,
permissions, and network access. Queued jobs with a healthy listening runner
usually indicate a label mismatch.

## CI workflow

The hosted ARM runner joins Tailscale as an ephemeral `tag:ci` node before
accessing Attic. Apply the tailnet policy containing `tag:ci` first and authorize
that tag on the OAuth client used by the `TAILSCALE_OAUTH_CLIENT_ID` and
`TAILSCALE_OAUTH_CLIENT_SECRET` Actions secrets (auth-key write scope). The
existing tagged-node HTTPS grant permits cache access without SSH access.

The check job probes Attic metadata for every native Asahi kernel output. When
all outputs are cached, recipe export, artifact upload, and the entire ARM job
are skipped; tests and host builds still run. A missing output or cache-query
failure takes the normal build-and-publish path instead.

Run `just update github-actions` to refresh SHA-pinned actions locally. Major
version comments (such as `# v7`) track that tag; full versions (such as
`# v5.0.0`) advance to the newest stable release within the same major. Annotated
tags are resolved to commits. All lookups must succeed before workflows are
written. Review the diff and run `just check` before committing.

`just update all` runs the Actions, image, and Nix updaters sequentially.
The weekly (Monday 06:23 UTC) and manually triggered `Update dependencies` workflow runs
this command from `main`, checks the result, evaluates hosts, and publishes one
PR from `automation/dependencies`. Pushes to `main` merge the new main into an
existing dependency PR and revalidate it, without refreshing pins or opening a
new PR. Merge conflicts fail the workflow for manual resolution. That branch
is automation-owned; do not put unrelated changes there. Existing runner
SSH credentials allow private flake inputs to update too.

The SHA-pinned `peter-evans/create-pull-request` action handles commits, branch
publication, and creating or updating the PR. It closes the PR and removes the
automation branch when its changes are no longer needed.

Configure the Actions secret `DEPENDENCY_UPDATE_TOKEN` with a dedicated token
that can push repository contents, update workflow files, and create PRs (for a
classic PAT: `repo` and `workflow`; for a fine-grained PAT: Contents,
Workflows, and Pull requests write permissions). A PAT rather than the built-in
`GITHUB_TOKEN` ensures pushes and PRs trigger normal validation. Enable repository
policy permitting this token's access. The token is exposed only to the PR
action; branch preparation uses the read-only built-in token. No automatic
PR merge or deployment is performed.

- Self-hosted validation accepts pushes to `main` and PR branches within this repository. Branch writers are trusted with access to the runner's SSH key and shared Nix daemon. Fork PRs skip self-hosted validation; review external changes before transferring them to a repository branch. Skipped jobs are not proof of validation and may satisfy required-check rules.
- Each successful host build on main or a trusted same-repository PR immediately pushes its closure to Attic, independently of other hosts. Upload failures fail that host job. Documentation and deployment remain gated on all tests and host jobs succeeding on `main`. Cache credentials use the `ATTIC_TOKEN` Actions secret. The internal dependency workflow combines flake inputs, GitHub Actions, and shared container image catalog updates into one weekly PR. Image updates refresh digests without changing tag channels.
- After successful flake checks, main and trusted same-repository PR runs explicitly push the `ci-checks` closure to Attic. Upload failures block the test job, so caching does not depend on the background store watcher. Unchanged checks can be substituted on later runs; evaluation still runs normally.
- Before tests and host builds, an `ubuntu-24.04-arm` GitHub-hosted runner builds the native Asahi kernel for `becmac-pro` and pushes all its outputs to Attic. This runs for main and trusted same-repository PRs, using the existing `ATTIC_TOKEN` secret. The self-hosted check job exports the exact kernel and Attic client derivations with their source dependencies as a one-day artifact, so the ARM runner does not need private flake credentials. Cache/upload failures block downstream builds. The Mac uses the same native kernel derivation: deployment downloads it when cached and can build it locally otherwise.
- Logs and job durations are available in GitHub Actions. Workflow definitions live in `.github/workflows/` and are checked by `just check`.
- Successful `main` runs also deploy Grafana dashboards using the `GRAFANA_TOKEN` Actions secret; see the [monitoring runbook](../monitor/README.md).
